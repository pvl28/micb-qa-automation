# Как устроен проект — шпаргалка к интервью

## 1. Как проходит один сценарий (путь выполнения)

1. `mvn test` → Maven Surefire запускает `RunCucumberTest` (JUnit 5 Platform Suite).
2. Suite говорит: движок `cucumber`, фичи — в пакете `features`, glue (шаги + хуки) — в `md.micb.qa`.
3. Тег-фильтр приходит из `-Dcucumber.filter.tags` (по умолчанию `not @wip`).
4. Для каждого сценария PicoContainer создаёт **новые** экземпляры step-классов и `ScenarioContext`.
5. Хук `UiHooks.@Before("@ui")` открывает браузер → шаги работают через Page Objects →
   `@After` при падении прикладывает URL, скриншот, HTML страницы и закрывает браузер.

Скажи на интервью: «Каждый UI-сценарий получает чистый браузер, поэтому сценарии независимы
и их можно запускать в любом порядке».

## 2. Ключевые решения и почему

| Решение | Почему (простыми словами) |
|---|---|
| Page Object + компоненты (`Header`, `CreditCalculator`…) | Локаторы в одном месте; при изменении вёрстки правим один класс, а не 20 шагов |
| Только явные ожидания, implicit = 0 | Смешивание implicit и explicit даёт непредсказуемые задержки |
| `waitForDocumentReady()` ждёт ещё и обработчик темы | Cookiebot (`data-blockingmode="auto"`) запускает скрипты сайта ~через 1 с после `load`; клики в это окно теряются |
| Ожидание **результата** действия | Ждём `active` у меню, значение у слайдера, `staleness` таблицы после AJAX — то, что увидел бы пользователь |
| `BigDecimal` для денег | `double` даёт ошибки округления (0.1 + 0.2 ≠ 0.3) |
| Курсы не хардкодятся | Курс меняется каждый день; проверяем соотношения и формулу, а курс читаем со страницы |
| Инварианты графика вместо формулы банка | Банк считает проценты по фактическим дням — это не учебный аннуитет. Копировать формулу = тестировать свою копию. Проверяем внутреннюю согласованность |
| SoftAssertions | Показывают все сломанные валюты/строки сразу, а не только первую |
| `ScenarioContext` через PicoContainer | Передача данных между step-классами без static-полей (static = утечки между сценариями) |
| ThreadLocal в `DriverManager` | Готовность к параллельному запуску: у каждого потока свой браузер |
| Нет автоматических перезапусков | Retry прячет нестабильность; мы нашли причину (Cookiebot) и починили |
| jsoup для `load_exchange` | Endpoint возвращает HTML, а не JSON; парсим в объекты и проверяем данные, а не «200 OK» |

## 3. Истории для интервью (реальные, из этого проекта)

**«Флейки-тест меню».** Меню открывалось то со 2-го, то с 3-го раза. Я не стал добавлять sleep/retry:
- собрал диагностику (класс элемента, кто сверху в точке клика, сколько обработчиков);
- написал пробу через CDP, которая логировала `stopPropagation` со стеком;
- увидел, что ранние клики вообще не доходят до обработчика jQuery;
- нашёл в HTML `Cookiebot … data-blockingmode="auto"` — он откладывает скрипты;
- сделал правильное ожидание: «обработчик темы навешан». После этого — стабильно с 1-го клика.

**`?_gl=` в URL.** Тест ждал точный URL `/ru/`, а Google Analytics добавлял параметр.
Решение — сравнивать путь (`URI.getPath()`), а не строку целиком. Нашёл по логу «failed at URL».

**Переведённые слаги.** Я предполагал `/en/despre-banca/`, а реально — `/en/about-moldinconbank/`.
Вывод: ожидаемые данные берём из наблюдений, а не из догадок.

**Нет `<h1>` на страницах продуктов.** Проверка заголовка падала → вместо неё «хлебные крошки + title».
Отдельно можно завести замечание по доступности/SEO.

## 4. Примеры кода, которые стоит уметь объяснить

* `BasePage.waitForDocumentReady()` — составное ожидание готовности.
* `CreditCalculator.setSliderValue()` — ввод «как пользователь» (клик → текст → Enter) и ожидание фиксации значения;
  `ignoring(StaleElementReferenceException)` — почему DOM пересоздаётся.
* `ExchangeSteps.converterResult()` — ожидаемое значение = сумма × курс, `HALF_UP`, допуск ±0.01.
* `CreditCalculatorSteps` — инварианты графика; почему допуск «1 копейка на строку».
* `ApiSteps.paginationHeaders()` — `X-WP-TotalPages = ceil(X-WP-Total / per_page)`.
* `ApiSteps.errorCode()` — негативные API-кейсы проверяют код ошибки, `data.status` и сообщение, а не только статус.
* `UiHooks.attachDiagnostics()` — почему диагностика в `try/catch` не должна скрывать исходную ошибку.
* `learning-lab/RateConsumer` — manual ack, idempotency (`ON CONFLICT DO NOTHING`), dead-letter queue.

## 5. Вопросы, которые могут задать, и короткие ответы

* **Чем Cucumber помогает?** Сценарии читают аналитики/бизнес; Gherkin — живая документация; теги управляют наборами.
* **Background vs Hooks?** Background — бизнес-предусловие, видно в фиче; Hooks — техника (браузер, скриншоты).
* **Scenario Outline?** Один сценарий × таблица данных (суммы конвертера, продукты меню).
* **Почему не Thread.sleep?** Медленно и ненадёжно: либо ждём лишнее, либо недостаточно.
* **Как тестировать PostgreSQL/RabbitMQ в банке?** Проверка записей после бизнес-операции через SQL,
  чтение/публикация сообщений в очередь, проверка DLQ и идемпотентности — показано в `learning-lab`
  (на Testcontainers, с синтетическими данными).
* **Как связать с Xray?** Cucumber JSON → REST import; сценарии помечаются тегами с ключами Jira-тестов.

## 6. Как запустить у себя (macOS)

```bash
# один раз: установить JDK 21 и Maven (например, через SDKMAN или Homebrew)
cd micb-qa-automation
mvn test -Dcucumber.filter.tags="@smoke"
open target/cucumber-reports/cucumber.html
```
